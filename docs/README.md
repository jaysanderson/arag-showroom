# ARAG Showroom documentation

The showroom is a portal, not a product on the ARAG platform — it holds no Knowledge Box and
consumes no ARAG API. It doesn't need the full four-way (developer/architecture/business/product
marketing) docs structure the three products use; this short set of pages covers what an
administrator and an engineer actually need.

| Page | For |
|---|---|
| [Admin guide](admin-guide.md) | Running the portal day to day: users, invites, access requests, audit, system status |
| [Architecture](architecture.md) | How the showroom is put together, request flow, the permission model |
| [Deploy](deploy.md) | Fly.io deployment runbook: launch, secrets, deploy, re-sync, rollback |
| [Content sync](content-sync.md) | How `scripts/sync-content.ts` works and how to re-run it |
| [White-labelling the public pages](white-label-pages.md) | `BRAND_*`, the copy files, and what a partner can and cannot rebrand |
| [Screenshots](screenshots/) | Full-page captures of every public page at 1440 px and 390 px, regenerated by `make screenshots` |

See also, at the repo root: [README.md](../README.md) (quick start, roles, API), [SECURITY.md](../SECURITY.md),
[DECISIONS.md](../DECISIONS.md), [CHANGELOG.md](../CHANGELOG.md), [CONTRIBUTING.md](../CONTRIBUTING.md).

Each product's own documentation (developer, architecture, business, product-marketing) is synced
into `content/<slug>/docs/` and is browsed inside the portal at `/p/<slug>/docs`, not duplicated
here.
