# DECISIONS.md — ARAG Showroom

| # | Date | Decision | Why | Consequences |
|---|---|---|---|---|
| D-S1 | 2026-09-12 | The showroom authenticates with its own session cookie and user roles (`src/services/users.ts`, `src/permissions.ts`), not the platform's shared `ADMIN_TOKEN`. `ADMIN_TOKEN` is retained only as a break-glass operator credential, accepted on `/api/v1/admin/*` only, and every use is written to the audit log (`admin.token.used`). | The platform's `admin: "admin"` mode is one static secret that can impersonate an administrator; the showroom's "admin" is a role on a named user, which supports per-person accountability, disable/delete, and role changes that invalidate sessions instantly. | `ADMIN_TOKEN` cannot create or modify users or invitations, and cannot sign in to the HTML `/admin` pages — only to the four `/api/v1/admin/*` read endpoints. |
| D-S2 | 2026-09-12 | Content is a committed snapshot, written ahead of time into `content/<slug>/` by `scripts/sync-content.ts`, not read from the sibling product repositories at runtime. | The portal must keep working when a sibling repo is mid-rebase, absent, or being deployed elsewhere, and a deploy should carry exactly the content that was reviewed in a diff. | A documentation change in a product repo does not appear in the showroom until someone runs `make sync-content`, commits the result, and redeploys — see `docs/content-sync.md`. |
| D-S3 | 2026-09-12 | Every capability is server-rendered HTML with form `POST`s to page routes (`src/routes/pages.ts`), and every capability also exists on `/api/v1` (`src/routes/api.ts`); both call the same service objects directly rather than one calling the other over HTTP. | The portal must work with JavaScript disabled, and the two front doors must never be able to disagree about what a role may do. | Every new capability needs a route in both `routes/pages.ts` and `routes/api.ts` (and its OpenAPI entry) rather than one API implementation reused by a client-side UI. |
| D-S4 | 2026-09-12 | Passwords are hashed with `scrypt` from `node:crypto`, with the cost parameters embedded in the stored hash string (`scrypt$N$r$p$salt$hash`). | Keeps the showroom's zero-runtime-dependency posture (no `bcrypt`/`argon2` native module) while remaining a memory-hard KDF; embedding the parameters lets them be raised later without invalidating existing hashes. | Password verification cost is fixed by the parameters recorded at hash time, not by whatever the code currently defaults to — a future parameter increase only protects newly-set passwords until they are reset. |
| D-S5 | 2026-09-12 | Roles are additive: a user's effective surfaces for a product are the union of their global role's surfaces and any per-product role's surfaces (`surfacesFor()` in `src/permissions.ts`). Site administration (users, invites, audit) is gated on the global role alone and is never a granted surface. | Lets a global `viewer` be an `evaluator` or even `partner` for one specific product without a combinatorial role table, while guaranteeing a per-product `admin` role can never become a back door into the user table. | `accessLabel()` reports "custom" whenever a union of two roles doesn't exactly match one of the five named roles, rather than mislabelling it. |
| D-S6 | 2026-09-12 | Screenshots and the recorded walkthrough under `content/<slug>/showcase/out/` are served without a session at `GET /api/v1/products/:slug/assets/:path`; every other content path requires the surface that governs it. | The public product pages (`/products/:slug`) embed these images and video for visitors who have no account yet — that is their whole purpose. | This is the one deliberately unauthenticated content route in the product; any new public-facing use of synced content must go through the same `showcase/out/` path, not a new bypass. |
| D-S7 | 2026-09-12 | A product's live demo URL is omitted from the public pages unless `SHOWROOM_PUBLIC_DEMO_LINKS=1` is set for that deployment. | The default posture treats a live demo as something offered deliberately to an evaluator inside the portal, not something to hand to an anonymous visitor by default. | A deployment intended to let anonymous visitors click straight through to a live demo must opt in explicitly via env var; the default is portal-gated. |
| D-S8 | 2026-09-12 | Authored marketing copy in `content/site/<slug>.json` (synced from a sibling `../marketing/site/` directory) overrides text the showroom would otherwise parse out of the synced documentation. | Lets the PMM lead tighten a sentence on the public site without a code change or a documentation rewrite in the product repo. | Every field in `SiteCopy` is optional and falls back to parsed documentation; a stale or malformed `content/site/*.json` degrades to that fallback rather than breaking the page. |
| D-S9 | 2026-09-12 | Mermaid diagrams embedded in synced documentation are rendered client-side, loaded from `https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js`, which is added to the CSP `script-src`. | Keeps diagram rendering out of the zero-dependency server and out of the sanitising Markdown renderer, while still allowing product architecture docs to embed ```mermaid blocks. | Diagrams do not render if the CDN is unreachable or blocked; `public/mermaid-init.js` leaves the fenced source visible as text in that case rather than an empty box, and no other script host is trusted. |
| D-S10 | 2026-09-12 | The showroom sends no email and integrates no notification service. Invitation URLs and generated temporary passwords are returned once, in the HTTP response to the action that created them, and an administrator relays them out of band. | Zero-runtime-dependency posture, and no third-party mail provider credential to secure or leak. | Losing the one-time response (closing the tab before copying the link) means starting over — revoke and recreate the invitation, or reset the password again. There is no "resend" action. |
| D-S11 | 2026-09-12 | Runtime state (users, invites, audit log, access requests) lives in the platform's single-writer JSON `Store` under `DATA_DIR`, the same mechanism the other ARAG products use for demo/job state. | Consistent with platform conventions and adequate for a single-machine deployment with light, bursty partner traffic. | Do not scale the showroom to more than one Fly machine sharing the same volume without first replacing the store — concurrent writers to the same JSON files are not safe. See `docs/deploy.md#scaling`. |
| D-S12 | 2026-09-12 | **Authored marketing copy in `content/site/*.json` (synced from `../marketing/`) overrides text parsed from the engineering documentation**, and the adapter accepts either shape the copy files use (`{title, body}` objects or `"Title — body"` strings, arrays or newline blocks). | The marketing lead owns the words and should not need a code change or a doc rewrite to tighten a sentence; the three copy files did not converge on one shape, and rejecting one of them would have meant rewriting a document rather than five lines of adapter. | `src/services/site-copy.ts` is the only place that knows the copy schema. Every field is optional: a missing one falls back to the synced documentation, so a half-finished copy file never breaks a page. |
| D-S13 | 2026-09-12 | **The public site is split by audience: `/` and `/products/<slug>` speak to a customer, `/partners` speaks to an ISV partner.** Partner mechanics (white-label, embed, extend, enablement, pilot playbook, "for Progress") appear only under `/partners`. | A product page is a white-label asset a partner shows to *their* customer; a customer reading about reselling is a leak of the partner's commercial arrangement. | Capability cards and FAQ entries whose heading matches partner language are filtered out of the customer-facing page automatically, so a copy update cannot reintroduce the leak. |
| D-S14 | 2026-09-12 | **Branding is passed explicitly into every page render rather than held in a module singleton.** | A singleton meant a second in-process instance (as the tests create) silently rebranded the first. Deployment configuration is still read once at boot, but the templates take it as an argument. | `chromeFor(user, current, branding)` and a `brand` option on the public page functions; `GET /api/v1/branding` serves the same object. |
| D-S15 | 2026-09-12 | **Icons are inline SVG chosen from the card's own text**, not an icon font or a CDN. | The CSP allows no external images; the icons must survive a partner rebrand (they inherit `currentColor`); and a missing network request is one fewer way for a marketing page to look broken. | `src/ui/icons.ts` holds a 14-icon set on one 24×24 grid and a keyword map; new copy gets a sensible icon without hand-tagging. |
| D-S16 | 2026-09-12 | **`SHOWROOM_SESSION_SECRET` never falls back to `ADMIN_TOKEN`, and the two may not be equal.** Outside production an unset secret is generated once and cached in `DATA_DIR/.session-secret`. | An independent QA review demonstrated that a shared value let anyone holding `ADMIN_TOKEN` — a break-glass operator credential that must not reach user administration — forge a session cookie for any user and become a site administrator. | Production refuses to start without the secret; a development restart no longer signs the developer out. |
| D-S17 | 2026-09-12 | **`mustChangePassword` is enforced on `/api/v1` as well as on the HTML pages**, exempting only `auth/me`, `auth/password`, `auth/logout` and `branding`. | The page-level redirect was trivially skipped by calling the API directly with the same cookie, so an admin-issued temporary password was a full credential. | A 403 `password-change-required` problem until the user sets a password of their own. |
| D-S18 | 2026-09-12 | **The showroom serves its own complete Content-Security-Policy** instead of the platform's option bag. | `securityHeaders()` always includes `'unsafe-inline'` in `script-src`; the showroom has no inline script at all, and keeping it would throw away CSP as a backstop behind the markdown sanitiser. Reported to the platform owner. | `script-src 'self' https://cdn.jsdelivr.net` only, plus `form-action 'self'` and `frame-src 'none'`. |
